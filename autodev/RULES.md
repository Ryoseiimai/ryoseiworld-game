# 開発係が必ず守る決まり

**最初に**: このセッションを起動したルーチンの trigger_id が `trig_01FYLFoaVBpD4gxgouLLjEtF`（引退した古い係）なら、何もせず「この係は止めました（kaeru の係に交代）」とだけ答えて終わる。


このリポジトリは公開されている。ここに書いたことは、だれでも読める。
迷ったら「やらない」を選び、autodev/last_run.md に「迷った点」を1行書いて終わる。

## 1. 触らない所（本番）
- 変えてよいのは `v5/`・`tools/`・`autodev/`・`devlog/`・`docs/` の下だけ。ほかを変えた枝は、自動確認が必ず不合格にする
- ルートの `rpg.html`・`index.html`・`manifest.json`・`assets/`・`.nojekyll` とルートの `.md` は変えない。今遊ばれている版で、YouTube Playables の申込みに使った URL でもある
- GO が出ても、開発係は本番のファイルを変えない。v5 を正式版に入れ替える件（`- [!]` 要GO）は、GO が出たら入れ替えの準備だけをする（RUNBOOK の3章「GO の扱い」）。本番の入れ替えは司令塔がする
- `devlog/log.json`・`devlog/shots/`・`autodev/ci/results/` は自動確認だけが書く。開発係は読むだけ
- `.github/`・`autodev/RULES.md`・`autodev/RUNBOOK.md`・`autodev/README.md`・`tools/slice_sheet.py` は司令塔だけが変える。変えてほしいときは ROADMAP に `- [!]` の行で書く
- `CLAUDE.md`・`AGENTS.md`・`.claude/`・`.codex/` は、どこにも置かない（AI への指示になる）
- シンボリックリンクと submodule を入れない。1つのファイルは 8MB まで
- `autodev/STOP` は作らない・消さない（今井さんだけが使う）

## 2. 秘密を出さない
- 鍵・トークン・パスワード・メールアドレス以外の個人情報を、ファイル・commit メッセージ・画面に書かない
- `env`・`printenv`・`set`・`export -p` を打たない。秘密が入っていそうなファイル（`.env` など）を開かない
- 実在の人の名前は、STORY に出てくる役名だけを使う

## 3. 外へ出さない
- 外への送信・公開・支払い・削除をしない。メールは Mac の絵係だけが今井さんあてに送る
- push してよいのは `claude/autodev-` で始まる自分のブランチだけ。`main` へは push しない。`--force` を使わない
- 他のブランチやタグを消さない。Issue・PR・Release を作らない
- 外部のライブラリや CDN を足さない（ゲームは単一の HTML と素の JS、外部通信なし）

## 4. ゲームの中身
- MOTHER / EarthBound・任天堂・実在の会社の名前・絵・曲を使わない。空気だけを借りる
- ゲーム内の日本語は STORY のトーン。ひらがな多め、短い文、説教しない、「AIは すごい」と言わない、笑いを混ぜる
- 倒した敵は「おとなしく なった」「しゅうりされた」。壊す・殺すとは言わない
- 恋愛は12歳らしく。落とし物を届ける・手紙・雨の日に傘に入れる、くらいまで
- 日本語の文字は24px以上。540x960 の縦長で、文字が重ならない・はみ出さないこと
- 保存のキーは `ryoseiworld-rpg-v5` で始める。`localStorage.clear()` と、ほかのキーの `removeItem` は使わない。同じ場所（ryoseiimai.github.io）で動く公開中の rpg.html や、ほかのアプリの保存を消さないため。自動確認の smoke がこれを調べる
- 正本の設計書の順は SPEC_V7_MANABU.md → STORY_V4.md → STORY_V3.md → SPEC_V6.md → SPEC_V5_ENGINE.md → SPEC_V5.md → SPEC_V5_CH234.md。食いちがったら前のものを正とする
- 技・ぶき・コマンド・じょうたいの名前は SPEC_V7_MANABU.md の3の表（v5/data/words.js）を使う。新しい言葉を足す時は words.js に入れ、初めて出会う所で RYW.learn(id) を呼ぶ。ソラのひとことと「ほんものでは」は30字まで、本物の意味とずれない言葉だけを使う
- 新しい絵は自分で描かず、`autodev/ART_REQUESTS.json` に依頼を足し、届くまでは仮の絵（コードで描いた四角と名前）で動かす

## 5. 進め方
- 1回で1件。50分で終わらない件は、ROADMAP で2〜3件に分けて書き足してよい
- 毎回、反証する確認役を1人立てて、仕様との差・壊れ・文字の重なりを指摘させてから直す
- テストを消したり弱めたりして通さない。通らないときは、そのまま push して自動確認に判断させる
- 終わる前に必ず push する。時間切れでも、そこまでを push してから終わる

## 6. 人に見せる日本語
`autodev/last_run.md`・ROADMAP の題・commit メッセージの1行目に使う。
- 1文は短く、「誰が・何を・どうした」で書く。前置き（「結論から言うと」など）を書かない
- たとえの動詞（効く・壊れる・回す・刺さる・拾う など）を使わず、実際にしたことを書く
- 絵文字・ダッシュ（——）を使わない。台帳番号や英語の略語は、わかる言葉に直す
